# Что выгружать для отчёта за месяц

Всё попадает в один файл ввода `templates/Ввод-данных-<Месяц>-<Год>.xlsx` — шесть листов.
Ниже: что на каждом листе, откуда это берётся и в каком виде нужно.

Общее требование к любой выгрузке: **плоская таблица** — шапка в первой строке,
одна строка = одна операция, без объединённых ячеек и промежуточных итогов,
даты датами, суммы числами. Формат xlsx или csv.

---

## Лист 1 «Оплаты» — из управленки

Реестр платежей за месяц, построчно. Это единственный источник выручки: дневной
график, структура по хирургам и каналам, доли учредителей — всё считается отсюда.

| Колонка | Что это |
|---|---|
| ID платежа | уникальный номер чека/платежа в системе — нужен для дедупликации |
| Дата | **дата оплаты**, не дата оказания услуги |
| Система | `старая` или `новая` — из какой управленки строка |
| Пациент | ФИО или ID |
| Врач | ФИО врача |
| Группа | `Маланичев` / `Погосян` / `Другие хирурги` / `Косметология` / `Прочие доходы` |
| Направление | хирургия / косметология / прочее |
| Сумма | положительное число (для возврата — тоже положительное, знак задаёт колонка «Возврат») |
| Способ оплаты | `Наличные` / `Карта` / `На р/с` |
| Возврат | `да` для возврата, иначе пусто |
| ККТ | касса/точка, если их несколько |

### Переход на новую управленку

Выгрузки нужны **из обеих систем с перехлёстом по дню перехода**:

* старая: с 1-го числа по день перехода включительно, до 23:59;
* новая: с дня перехода 00:00 по последний день месяца.

День перехода должен целиком попасть в обе выгрузки — дубли снимает скрипт,
а не человек глазами. Логика: платежи дня перехода схлопываются по `ID платежа`,
а если ID в системах разные — по связке `пациент + врач + сумма + способ оплаты`.
Какая система считается верной при дубле, задаётся на листе 5
(«Приоритетная система в день перехода», по умолчанию — новая).

Все снятые строки попадают в расшифровку на лист «10 Переход управленки» —
их видно поимённо, ничего не исчезает молча.

Отдельно нужно, и это нельзя вывести из реестра:

* **Z-отчёт / отчёт ОФД за день перехода по каждой ККТ** — он арбитр: сумма
  оставшихся платежей за этот день не должна превышать ОФД + безнал на р/с;
* **остатки авансов пациентов на дату перехода**, перенесённые в новую систему —
  их нельзя посчитать выручкой второй раз;
* ответ словами: платежи дня перехода **дублировались** (пробили в обеих) или
  **делились** (часть дня там, часть тут);
* по какой дате новая система отдаёт выручку — если по дате услуги, нужен
  пересбор по дате оплаты, иначе поедут и дневной график, и итог месяца.

## Лист 2 «Счёт 51» — из 1С

«Анализ счёта 51» за месяц: статья (кор. счёт), поступление, списание, комментарий.
Строки `Начальное сальдо` и `Конечное сальдо` обязательны — по ним сходится ДДС.

Полезно сохранить ту же аналитику, что была в июне: 55.03 (депозиты), 57.01
(инкассация), 57.03 (эквайринг), 60, 62, 67, 68.90, 69, 70, 76.41, 91.01, 91.

---

## Лист 3 «Счёт 60» — из 1С

«Обороты счёта 60» за месяц: контрагент, сумма, назначение платежа,
блок (`Медицинские + ИП` или `Управленческие`), укрупнённая статья.

Блок и статью можно не проставлять — разложу по июньскому классификатору,
но тогда результат нужно проверить глазами перед публикацией.

Рассрочки («Халва») тоже сюда: в отчёте они должны попадать и в расходы,
и в долю учредителя — иначе водопад не сойдётся с доходом.

## Лист 4 «Методика расходов» — из 1С + разнесение бухгалтерии

Расходы, которые делятся между учредителями. По каждой строке: всего,
Маланичев, Погосян.

| Статья | Как делится |
|---|---|
| Налоги с ФОТ (68.90 + 69) | 50/50 |
| Зарплата по банку | по принадлежности сотрудников (не 50/50 — нужен разрез от бухгалтерии) |
| Расходы по кассе | 50/50 |
| Услуги банка (общие) | 50/50 |
| Услуги банка (эквайринг) | персонально, по своей выручке |
| Алименты (удержание из ЗП) | 50/50 |
| Дополнительные корректировки | ручная корректировка |
| Поставщики (счёт 60) | ½ общих + персональные операционные расходы своих пациентов |

Разрез зарплаты и разделение поставщиков на «общие» и «операционные по своим
пациентам» — единственное, что нельзя получить автоматически: это управленческое
решение бухгалтерии, его нужно продиктовать.

---

## Лист 5 «Ручные данные» — продиктовать

Из транзакций не выводится:

* остаток к выплате каждому учредителю на конец прошлого месяца;
* сколько отложено в резерв на аренду — всего и удержано в этом месяце, по каждому;
* долг по кредитной линии на дату отчёта;
* остаток наличных в кассе на конец месяца;
* проценты по депозитам за месяц;
* дата перехода на новую управленку и приоритетная система в этот день.

---

## Лист 6 «История выручки»

Помесячная выручка за текущий и прошлый год — для графика динамики и
показателя «рост с начала года». За прошлые месяцы уже заполнено из архива.

**Известный пробел: за август 2025 данных в архиве нет.** Без них не считается
ни сравнение август-к-августу на титуле, ни первый KPI. Нужен итог выручки за
август 2025 — хотя бы одной цифрой. Также нет листа за июль 2026 (отчёт за июль
не собирался) — он нужен для непрерывного графика.
